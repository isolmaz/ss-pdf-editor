Privacy and Security Guarantee

SsPdfEditor is designed to work 100% locally. The contents of your documents never leave your device.

Your Documents Are Never Uploaded

The PDF files you open or edit are processed directly in your own browser's temporary memory. Not a single byte of data is sent to a server. The server only serves static files; there is no API a document could be uploaded to.

No Account or Sign-in Needed

You do not need to provide an email address, create an account or register. Just open it and start working on your document.

No Third Parties

The engines, OCR language packs and fonts are served by this site; no request goes to any third party. A strict content security policy (CSP) allows connections to this site only. There are no cookies and no analytics. If you click an external link inside a PDF, the address opens in a new browser tab, so the editor and your unsaved work stay where they are.

Camera Only When You Scan

When you scan a document, the browser asks for your camera first. The picture is processed on your device and only the pages you keep become the PDF; no sound is recorded, and the camera turns off when you close the scan window. The site’s response headers allow the camera for this site only.

Control Over Saving and Downloading

Whether to save or download the final file you edited is entirely up to you. So that a window closed by mistake loses nothing, unsaved changes are kept as a draft in this browser only and come back when you open the editor again; closing the document's tab in the editor deletes its draft too. If the browser's storage refuses a document's recovery copy (when it is full, for example), the document still opens and the notice says so and why; until a draft save succeeds, unsaved changes would not survive a closed tab or a crash.

What Stays on Your Device

None of it goes to a server; it stays in this browser's own storage only:

  • Drafts: unsaved work and, where needed, the document's source copy (the browser's private file system, OPFS).
  • The recent documents list: file name, size, page count, when it was opened and its star, if you gave it one (localStorage). In Chromium-based browsers a reference to the file is kept too, so it can be reopened (IndexedDB); not the file's contents.
  • Signature pictures you keep with “Remember on this device” (six at most, localStorage; each is deleted from the signature dialog), and the trust roots and revocation lists you import (the app’s own settings folder, OPFS; they stay until you remove them).
  • Theme, language, interface mode and your recent commands.
  • The static files of the app, the PDF engines, the OCR language packs and the fonts, for offline use (the service worker’s cache). Document bytes never enter the cache.

Opening a document that asks for a password, with its password, starts a sensitive session: that document's draft, source copy and file reference are not kept, no signature picture is remembered while it is open, and the list shows only its name, size, page count and opening time. The password is kept in memory only and is never written anywhere. You can turn the same setting on yourself with Settings → Privacy and storage → Sensitive session; turning it on deletes that document's stored copies. Delete a document's stored copies with Delete stored copies of this document in the same section, and an entry of the recent list with the delete button beside it. Deleting does not overwrite the bytes on disk; it is not secure erasure.
